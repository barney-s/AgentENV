## Summary of Planned Run "gvm"

This run deploys AgentENV onto a dedicated Google Compute Engine (GCE) VM by compiling it directly from source on Ubuntu 24.04 LTS with nested virtualization enabled, matching the official [AgentENV Manual Compile Deployment Guide](https://kvcache-ai.github.io/AgentENV/latest/deployment/manual-compile.html).

### Resources to be Created
- **GCE Compute Instance:** `agentenv-gvm-vm`
  - Machine type: `n2-standard-4` (4 vCPUs, 16 GB RAM)
  - Zone: `us-central1-a`
  - OS Image: Ubuntu 24.04 LTS (`projects/ubuntu-os-cloud/global/images/family/ubuntu-2404-lts-amd64`)
  - Boot disk: 50 GB `pd-balanced`
  - Nested Virtualization: Enabled (`--enable-nested-virtualization`) for `/dev/kvm` hardware acceleration
  - Network tags: `agentenv-node`
  - Labels: `repo-agent-instance=agentenv-gvm`
- **Firewall Rule:** `agentenv-gvm-allow-http`
  - Allows ingress TCP on port 8000 for target tag `agentenv-node`

### Notes for the Owner Before Approval
1. **Compilation Time:** Compiling AgentENV from source in release mode on an `n2-standard-4` VM takes approximately 5–8 minutes.
2. **Nested Virtualization:** Nested virtualization is required for `/dev/kvm` support so Firecracker microVMs can boot.
3. **Public Exposure:** Port 8000 is opened by the firewall rule. While AgentENV generates an API key in `/var/lib/aenv/secrets/api-key` on first boot, HTTP traffic does not encrypt credentials in transit. For production exposure, configure a reverse proxy with TLS termination.
